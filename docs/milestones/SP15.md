## Goal

Everything left in the definition of done is writing, and all of it lands in one file. A reader who was not there should finish the README knowing what runs today, what used to run, what it cost, and which claims they can check for themselves.

This is the milestone that turns a working repository into a documented one. It is also the one a reviewer reads first, and SHIP makes it the page a stranger can judge in five minutes.

## Check it

Run `bash .github/scripts/check-local.sh` at every checkpoint. What its output means, how to fix a red step, and when GitHub is the authority are explained once, in [SP1](SP1.md#how-to-see-your-results); this brief's own steps and its own failures are below.

### How to see your results


The check prints one row per step, in the order the parts appear, and a step is green only when its file is in place and every assertion in it passes. A red row prints the reason underneath it, naming the file, the value, or the attribute that is wrong. CI prints the same rows in the job summary, so the local run and the remote run read identically.


**Locally:** `bash .github/scripts/check-local.sh`. **On the pull request:** **Actions**, newest run, **Summary**.

| Step | Checks |
|---|---|
| 1 (readme) | every section heading, both diagrams, the benchmark table with both rows, `nodejs24.x`, the 60 to 90 second capture, the "why this can't run away" line in either spelling, the three cap terms, the destroy script, the Release link, and the idempotency entry. The date on each decision line is SHIP's check, not this one |
| 2 (policy) | both policies' statement ids, and that the ARNs carry placeholders |

Reading a failure:

- **Step 1 ❌ on a heading**: the heading text has to match. `## Why this cannot run away` is not `## Why it can't run away`.
- **Step 1 ❌ on `1,000`**: the table's event count is written with a comma.
- **Step 2 ❌ on `PROJECT-landing-ACCOUNT_ID`**: a real bucket name reached the file. Replace it with the placeholder.

## After the merge

Merge the pull request on GitHub, then clean up the branch:

```bash
git switch main && git pull
git branch -d sp15-readme
git fetch --prune
```

`git branch -d` refuses after a squash merge, because the branch's commits are not in `main`; `git branch -D sp15-readme` is the same delete. The remote branch is already gone: `delete_branch_on_merge` removes it when the pull request merges.
